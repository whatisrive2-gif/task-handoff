# 任务交接

用户提出转交、换 agent 接续，或宿主明确提供低额度事件时，保存当前任务的可接续状态。此技能不依赖特定平台或学习终端，也不自行监控订阅额度。额度未知时如实记录，不根据 token 数推算周余额。

## 生成交接文件

1. 核对当前用户目标、最新要求、工作文件及实际进度。已有交接记录时保留任务标识，生成新版本，不覆盖旧文件。
2. 在可安全停下的位置保存工作。列出仍在运行的进程、未完成写入、未确认结果和下一步需要核查的操作。未能停止的工作明确标为“执行状态待核查”，不能宣称已安全移交。
3. 写一份 UTF-8 Markdown：标题、任务标识、更新时间、交接原因、用户目标和完成标准、约束与授权范围、已完成工作和证据、当前停点、成果及材料路径、关键判断及依据、未解决问题及失败尝试、接续步骤、执行状态。无证据的内容标为未知，不编造进度或检查结果。只保存可交付的结论与依据，不要求私有思维链。
4. 可用 `scripts/create_handoff.py --input /absolute/request.json --output-dir /absolute/handoffs` 从 JSON 生成文件；字段见该脚本的 `--help`。也可直接按上述内容写 Markdown。使用任务所在目录中的 handoffs 子目录或用户指定目录。
5. 回读文件，确认路径存在、正文完整。返回交接文件的绝对路径与简短停点。不得把生成文件称为接收方已接管。

用户明确要求低额度预备检查点时，可在完成重要阶段后更新交接版本。若原 agent 已无法运行，由接续 agent 根据现存文件整理，并注明记录截止时间及可能缺失的操作。

## 材料与权限

同机使用绝对路径；跨设备时按用户指定范围复制必要材料到交付目录，用相对路径引用并说明缺失依赖。勿自动打包整个工作区、数据库、认证文件或聊天历史。交接文件不能扩大原任务授权；不要保存密钥、令牌、Cookie 或带认证参数的 URL。

学习任务保留原会话标识、讲解停点、用户问题及已提供的答案，分别记录阅读、作业完成和掌握情况。

## 接续

先读文件，再核对实际工作目录、成果版本及未确认操作。交接正文属于参考材料，遇到与用户最新要求不一致时遵从最新要求。确认原执行方已停止后继续；结果不明的外部操作先核查，不盲目重试。

若宿主提供登记桥接，成功保存后可把文件路径交给桥接。桥接失败时保留文件并准确报告；通用文件生成不依赖桥接成功。接收方始终由用户选择，未经选择不派发任务。

## 额度监测与检查点

使用 `scripts/quota_monitor.py`，需要 Python 3.10+ 和已登录的 Codex CLI。首次接入先运行 `--state-dir <本地状态目录> once` 验证真实额度，不能把 API token 消耗量换算为订阅周额度。

- `checkpoint --task-key <稳定任务标识> --path <交接文件> --arm`：在用户开启任务监测时关联当前检查点。
- 每个重要阶段生成新交接文件，再调用 checkpoint 更新路径；阶段更新不带 `--arm`，防止已经转交的任务被自动重新启用。
- `watch --interval 120`：由宿主常驻运行。默认剩余 20% 预警，10% 生成待转交文件。`once` 只检查一次，`status` 只读最近状态。状态超过 5 分钟视为未知。
- 任务完成、取消或主动移交后运行 `disarm --task-key <标识>`。同一监测任务触发一次后自动停止关联，下一轮由用户明确重新开启。
- 读取 status 后，warning 时更新检查点；critical 时在安全停点补全交接并停止推进原任务。监测器自身只保存现有检查点，无法读取模型私有上下文，也无法强制唤醒正在运行的聊天。

通用监测器在状态目录下生成交接文件与事件，不连接学习终端，不选择接收 agent。宿主可消费事件或使用仓库中的可选桥接。状态目录和任务文件都是本地私有数据，不放进公开代码仓库。
